# 《保卫萝卜》塔防核心参考分析

> 用途：分析成熟休闲塔防的玩法、UI、交互和关卡逻辑，为《叮咚！夜班开始》提供结构参考。本文只提炼通用机制，不复制《保卫萝卜》的名称、角色、炮塔造型、地图、美术、音效、数值、文案或像素级 UI。

## 1. 参考结论

《保卫萝卜》的核心不是“可爱角色站在道路旁自动攻击”，而是把整张地图做成一块持续变化的塔防棋盘：玩家在大量可建空间中，用有限金币不断做出“建造、升级、清障、出售、转火”的选择。

官方资料强调其保留经典塔防核心、丰富炮塔和策略关卡；App Store 页面明确描述多种特色炮塔可自由摆放。实际关卡截图和攻略还表明，清除地图障碍能够获得金币并释放新的建造空间，使布局从开局的少量火力逐步扩张为完整防线。

因此，早期“每关只有4～6个明显圆形塔位”的原型虽然容易操作，但空间决策过少；此前效果图中角色与环境过大也削弱了塔防感。2026-09-26先在前三关恢复高密度布阵、清障扩张和紧凑UI；2026-09-27已将同一棋盘规范扩展到全部十关，并接入首批简洁Q萌精灵，继续验证实际体验。

## 当前实现进度

本文第2～8节还包含目标建议，不等于全部已实现；当前代码只支持手动指定障碍、优先攻击范围内最靠近终点的敌人，尚无手动指定敌人、默认自动清障和暂停时地图选择。新增这些行为前需单独验证价值。

- 全部十关各配置22个规则建造单元、12个开局空位和10个可清除障碍物。
- 玩家可点选障碍物，范围内店员在没有更紧急敌人时攻击；清除后获得零钱并立即开放原位置。
- 选中店员后同时显示升级与出售，出售返还累计投入的 65%。
- 常驻操作压缩为顶部状态和右下角三个紧凑道具按钮；建造、升级和出售继续跟随选中位置。
- 第4～10关已完成网格、障碍和波次经济迁移；全十关通过统一静态约束检查，不再豁免第3→4关。人工难度、清障策略和多种布阵仍待体验验证。
- 三名店员、底座、三类障碍及普通纸袋/疾行汽水罐/重型纸箱怪已接入精灵；用户反馈后补齐道具图标、店员缩略建造卡片和状态/上下文/结算首轮UI皮肤。道路继续沿关卡数据绘制，矢量UI底板与文字独立于图片；店长、入口/终点独立美术与多帧动作仍后置。
- 系统安全区、顶部平台胶囊、长屏上下延展和字号/热区约束已接入，不能因此视为本轮实屏或真机全机型验收完成，实际结果以测试记录为准。

## 2. 核心玩法循环

成熟的休闲塔防循环可以归纳为：

```text
观察路线、出怪口、终点、可建空地和障碍物
→ 用初始金币建立最小可用防线
→ 自动攻击来怪并获得金币
→ 在安全窗口指定炮塔清除障碍物
→ 获得额外金币或释放新的建造空间
→ 在建新塔、升级旧塔、出售转移和继续清障之间取舍
→ 针对高速、重甲、飞行或特殊敌人调整组合
→ 守住全部波次并完成关卡
```

这个循环有三个并行目标：

1. **守路**：不能只顾清障而漏怪。
2. **扩张**：不能只守住当前波次，否则后期缺少建造空间与经济。
3. **优化**：同一笔金币用于新建、升级或转移火力，会产生不同结果。

## 3. 关卡空间设计

### 3.1 地图首先是棋盘，其次才是插画

- 道路必须清晰，但不能占据绝大部分画面。
- 路线周围应存在大量可操作空地，不以 4～6 个大圆盘限制整个关卡。
- 装饰物不能只是背景填充；部分箱子、货架、纸袋、饮料箱和盆栽应成为可攻击障碍物。
- 障碍物被清除后，原位置释放为可建空间，并给予可预测的零钱奖励。
- 入口、拐角、长直线、终点前和多段道路重叠区应形成不同的火力价值。
- 玩家应该能看到防线从稀疏逐渐变得密集，这是局内成长感的重要来源。

### 3.2 我们的首版目标密度

- 每关配置 20～24 个潜在建造单元，而不是 4～6 个显眼塔位。
- 开局直接可用约 10～14 个单元，其余约 8～12 个由障碍物占据或暂时封锁。
- 空位、障碍物和清障后释放的位置必须共用同一套规则网格，并沿道路成行、成列或组成拐角阵列。
- 正常通关时预计建成 8～12 名店员；不要求填满全部单元。
- 建造单元在平时弱化或隐藏，点击有效空地时才显示吸附位置和建造菜单，让视觉上接近自由摆放，逻辑上仍保持可控的离散坐标。
- 店员尺寸必须明显缩小，避免单个角色和底座占据过多棋盘空间。
- 地图审计从“每个塔位是否有效”升级为“可建密度、清障扩张路线、关键火力点和满建遮挡是否合理”。

当前十关已落实22/12/10数量与50像素逻辑网格，后续仍需在750×1334和375×667视口核对新美术与热区，并在长屏/异形屏真机验证，不能只以配置数量判定密度合理。

## 4. UI 信息层级

参考关卡通常把局内信息压缩到顶部边缘，将绝大多数面积留给地图。截图中可稳定识别到金币、波次、倍速、暂停和终点耐久等高频信息，而炮塔选择和升级操作围绕当前点击对象出现。

我们的 UI 应遵循：

- 顶部只常驻零钱、便利店耐久、当前波次、倍速和暂停。
- 地图保持全屏主导，战斗区域至少占竖屏主要可视面积，不能被大型角色头像、说明牌或底部工具栏挤压。
- 三个全局道具缩成紧凑按钮，放在屏幕边缘安全区，不持续占用整条底栏。
- 建造菜单只在点击空地后出现，围绕点击点排列本关可用的 3～4 名店员，并显示价格。
- 选中店员时显示攻击范围、升级和出售；按钮随塔位选择上下或左右摆放，避开道路与屏幕边缘。
- 选中障碍物时显示目标描边、耐久条和预计零钱价值，不再弹出额外大面板。
- 暂停和结算可以使用全屏弹窗；正常战斗期间不使用大面积遮挡层。

## 5. 交互模型

### 5.1 建造

1. 玩家点击路线外的有效空地。
2. 系统吸附到最近的合法建造单元，并显示范围预览和店员选择。
3. 钱够的店员正常显示，钱不够的店员置灰但保留价格。
4. 点击店员立即建造；点击地图其他区域关闭菜单。

### 5.2 升级与出售

1. 点击已建店员，显示攻击范围和当前等级。
2. 附近出现升级与出售按钮；满级时升级按钮显示“已满级”。
3. 出售返还部分累计投入，允许玩家把前段失去价值的火力转移到后段。
4. 所有操作必须单击完成，不加入拖拽、长按或分支技能树。

### 5.3 清除障碍物

1. 点击可清除障碍物，将其设为当前集中攻击目标。
2. 范围内店员在没有更高优先级危险敌人时攻击该障碍物。
3. 再次点击或点击其他敌人/障碍物可切换目标。
4. 障碍物清除后播放零钱反馈，释放对应建造单元。
5. 怪物接近终点时自动取消低优先级清障目标，避免操作失误直接导致漏怪。

### 5.4 波次、倍速和暂停

- 保留我们已经实现的入口倒计时，避免突然出怪。
- 前 3 关可维持较少短波，后续逐步扩展到 5～8 个短波；增加波次不是为了拉长时间，而是给清障和扩建提供阶段节奏。
- 1、2、3 倍速继续作为正式功能；暂停时允许查看地图和选择下一步，但战斗时间不推进。
- 暂不强制手动放行下一波，先保持轻量自动波次；未来只在数据证明需要时评估“提前开波换奖励”。

## 6. 运行逻辑与状态优先级

### 6.1 攻击目标

建议优先级为：

1. 即将到达终点的危险敌人。
2. 玩家手动指定且位于攻击范围内的敌人。
3. 默认目标规则中的敌人，例如最靠近终点者。
4. 玩家指定且位于攻击范围内的障碍物。
5. 无敌人威胁时的默认障碍物目标。

清障不能覆盖紧急防守，这是保证轻量玩家不因一次误触立即失败的必要保护。

### 6.2 建造单元状态

每个建造单元只处于以下一种状态：

- `open`：可直接建造。
- `blocked`：被可清除障碍物占据。
- `occupied`：已有店员。
- `locked`：关卡机制暂时禁用。

障碍物、建造单元和塔位不能分别维护互相矛盾的坐标；关卡配置需要明确记录占用关系和清除奖励。

### 6.3 经济闭环

局内零钱来源包括初始零钱、击退敌人、波次奖励和清除障碍物；支出包括建造和升级。出售只返还部分投入，不能无损反复搬塔。

每关必须设计至少两个可理解的经济节点：

- 开局零钱刚好支持一种合理的初始防线。
- 第一段清障或第一波收入能够支持第一次扩建或升级。

困难应来自“何时扩张、在哪里扩张、先升级还是多建”，而不是单纯把敌人生命堆高。

## 7. 关卡设计逻辑

每关配置不再只有路线、少数塔位和波次，还需要：

- 潜在建造单元及其开局状态。
- 可清除障碍物、耐久、奖励和占用单元。
- 本关可用店员组合。
- 开局推荐但不唯一的第一步。
- 关键拐角、长直线和多路覆盖点。
- 每波敌人构成、清障窗口和预期经济节点。
- 至少两种可通关布阵，避免关卡只允许照攻略点击。

此前曾建议按关卡逐步讲解清障和出售；用户现已决定暂不制作新手引导。当前从首关起即可清障、升级与出售，前三关仅逐步增加可用店员，通过短开场提示、倒计时和操作反馈帮助理解，不增加强制教学流程。

## 8. 美术落地约束

- 店员是“可爱的店员炮台”，不是占据大片场地的独立主角立绘；装备、攻击方向和底座比表情细节更重要。
- 小浣熊店长应主要位于便利店终点或顶部小头像，不占据核心建造区。
- 角色/UI 继续采用原创便利店设定；参考作品只影响信息密度和交互结构。
- 道路、建造空地和障碍物必须具有比背景装饰更高的视觉优先级。
- 前期效果图中的大面积森林、木牌和灌木需要收缩，不能占用潜在建造空间。
- 效果图应体现多个潜在建造点、店员和可清除障碍，只用于方向参考；正式密度必须由真实22点配置、实际素材尺寸和游戏内操作验证。
