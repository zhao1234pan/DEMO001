# 跨仓库与全部分支维护

规范版本：2026-11-12.1。范围为 zhao1234pan/DEMO001～DEMO007，包括各仓库默认分支、其他远端分支和已知本地分支。

## 一份维护源与各分支副本

统一维护源在 DEMO007 默认分支。各分支都有相同版本的根 GAME_DEVELOPMENT.md、GIT_WORKFLOW.md 和分章资料，可在离线时读取。GUIDANCE_MANIFEST.json 保存规范版本、文件清单与 SHA256。

项目自己的玩法、平台身份、表结构、素材和当前进度继续在项目原位置维护。通用规范只提炼可复用方法，不搬运其他游戏的 AppID、广告位、身份材料或原始提交附件。

## 如何增加一条经验

按[经验模板](templates/LESSON_RECORD.md)记录触发场景、玩家或办理影响、已确认原因、最终处理、验证方法、适用范围和来源。区分规则缺陷、材料遗漏、工具失败和实际平台结果。

用户已确认的跨项目做法、重复出现且原因明确的问题，更新对应分章和经验条目。新提出但未验证的想法保留为待验证，不直接提升为所有游戏的强制规则。

用户修改过的文案和 UI 标准保留实际含义。新规则覆盖旧规则时修订当前结论，历史材料保留当时事实；不能在首页不断叠加互相冲突的“最新要求”。

## 主动维护的触发与完成标准

用户于 2026-11-11 明确要求：以后有新经验，Agent 主动总结并同步七仓库所有分支，无需每次提醒。此要求是后续游戏制作、软著与发行任务的持续工作约定。

- 每轮任务交付前主动检查：是否出现新的用户纠正、重复失败、经验证的修复方法、玩法/UI 判断、材料遗漏或实际平台反馈。
- 有稳定且可跨项目复用的结论，当轮写明触发、原因、最终处理、验证、适用范围和原提交来源，更新对应章节、条目、CHANGELOG、规范版本与摘要，再按下述流程同步七仓库全部现有分支（含 main/master），不用另等用户下达总结或推送指令。
- 只有项目特例时更新所属项目，未经验证的想法明确留待验证；没有新的稳定经验就不生成空总结、不增加无意义版本。
- 同步前读取 DEMO007 维护源最新提交，合并规范本身的并行新增，保留各游戏业务和其他任务工作。不得将本机过时副本反向覆盖维护源。
- 同步完成要记录实际覆盖分支、规范版本与远端核对；权限、网络、分支保护或工作树状态受阻时，保留具体待办与已完成部分，在后续任务开始时主动检查续办，不称全部完成。
- 这是每轮实际任务中的收尾动作，不是定时任务、Git hook 或后台常驻进程；没有活跃任务时不会自行运行。

## 更新和发布规范

1. 核对 DEMO007 维护源的当前版本和本任务来源，不覆盖别人新增的规范内容。
2. 更新相应章节、CHANGELOG 和来源记录，生成新的文件摘要清单。
3. 在个人仓库按本任务范围验证并提交；只同步规范文件、管理的阅读入口与必要的执行范围修订。
4. 枚举 DEMO001～007 的全部现有远端分支，合并已知本地分支清单；在每个分支自己的当前版本上增加规范提交，不把一个分支的业务树复制到其他分支。
5. 普通推送，不强推；目标分支在操作中变化时重新读取其最新提交，只重新应用规范差异。保护分支或权限拒绝时如实记录，不能绕过限制。
6. 回读每个远端分支的实际 SHA、规范摘要和读取入口。最后再枚举一次分支，补查执行过程中出现的新分支，记录覆盖时点和未覆盖原因。

仓库公开性保持原样。公开仓库只分发通用规范与去标识案例，详细研究索引和审计记录保存在私有维护仓库，不复制私有附件或原始日志。

## 工作区与历史保护

现有工作树的未提交、已暂存和正在进行的任务要保留。同一规范文件已有别人的修改时，分离本次规范差异；不能整文件顺带提交。更新未检出的分支使用隔离索引和该分支自己的基线，不切换用户的工作区。

已检出的分支按实际 HEAD 核对；发生并行更新时先重读，不覆盖。规范同步不移动冻结标签，不修改旧登记源码、游戏配置、图像、构建包或发布回执。过去发生的提交、当时未提交等事实不改写为今天的权限。

## 新电脑与新分支

从已更新的基线创建新分支会继承规范。取得旧分支或另一台电脑新增的分支后，先检查规范版本和摘要；发现缺失时补入本轮清单。

运行 `python tools/sync-game-guidance.py --check` 检查当前检出。需要跨仓库发布时使用 `python tools/maintain-game-guidance.py --source <规范维护源目录> --cache <独立缓存目录> --publish-all`；先执行同命令去掉 --publish-all 可盘点计划。工具只允许指定的七个个人仓库和规范文件，不操作 Biu 工作仓库。

完整来源索引与本轮覆盖报告位于私有 DEMO007 的 docs/team/research。扫描全部分支、关键案例人工复读、规范实际生效是不同的检查，本轮报告分别记录。
