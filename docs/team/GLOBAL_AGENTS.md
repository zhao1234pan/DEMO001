# 用户全局工作约定

## 游戏 UI 设计工作约定

- 用户于2026-11-14明确要求：规范由Agent内化并主动用于判断、自检，不以搜索结果或复述代替设计；用户要求先思考、调研或暂不设计时，不修改原型。
- 先明确当前任务与决定依据，按重要性、频率和时机取舍，去重复，再定层级、布局与规格；不用缩字、扩大容器或机械放大全部控件解决堆满内容的问题。
- 同屏明确阅读顺序和操作轻重。常用任务与关键依据优先，辅助管理按需展示；不隐藏必要费用和缺项，不让高频操作绕路。只改排版时保持功能与流程。
- 装备、物品和角色美术承担识别，数量及必要状态辅助判断；标签应增加信息，不逐图重复，也不把含义不明的操作全部换成无标签图标。
- 用邻近、留白、对齐、对比和有限强调分组；不为每块内容堆厚边框、醒目底色、金字和大按钮。适配美术时控制视觉重量。
- 核对实际预制体、设计分辨率、弹窗、字体与控件规格，理解参考界面的任务；外框尺寸相同不代表内容密度可套用，不推广单项目规格。
- 区分设计单位、设备像素、屏幕密度、网页缩放和平台pt/dp；检查可见尺寸、有效触区、间距及误触。数字达标和桌面截图缩小不等于手机适配。
- 交付前主动检查重点、阅读负担、主操作、增减删除误触、费用结果与二级页溢出截断。实际检查、真机和用户认可分别表述，脚本通过及放得下不代替体验判断。

## 按仓库归属区分 Git 操作

- 用户于 2026-11-11 明确区分两类仓库，替代此前“所有仓库均由用户提交推送”的宽泛规则。
- `biu_art`、`biu_client`、`biu_design` 三个工作仓库及其子目录、工作树：Agent 只修改本地并完成必要验证；Git 提交和推送由用户亲自操作，Agent 不执行，也不通过脚本、工具或自动流程代为操作。此限制优先于账号归属判断。
- 用户在 GitHub `zhao1234pan` 下的个人仓库（例如 DEMO003、DEMO006）：Agent 完成修改和必要验证后，应提交并推送本次任务改动，核对实际远端与本地提交。不要因涉及配置表而误套用 Biu 三仓库的本地保留规则。
- 操作前核对实际 Git 根目录、origin 归属、分支和工作区。只提交本任务改动，保留用户及其他任务未提交或已暂存的内容；不强推、不重写共享历史。共享分支合并和平台发布仍按具体授权执行。
- 当前任务若另有明确“本轮仅本地”或提交推送要求，以用户该次明确要求为准；仓库归属无法确认时不猜测。

- DEMO001～DEMO007 开始游戏制作、软著或发行任务时，读取仓库根 GAME_DEVELOPMENT.md、GIT_WORKFLOW.md、GUIDANCE_MANIFEST.json，再按任务读取对应分章和目标游戏当前约定。
- 用户已明确要求七仓库的全部分支持续维护通用规范，包含 main/master。规范维护可以在各分支自己的基线上提交推送文档、阅读入口与规范工具，不合并不同分支业务，不移动冻结标签，不改变仓库公开性。
- 新的稳定跨项目经验回收到 DEMO007 默认分支的维护源，更新版本和可追溯来源后同步各现有分支；项目特例、原始私有材料和平台身份保留在所属项目，不把它们变成通用默认值。
- 用户于 2026-11-11 明确要求主动持续维护，无需逐次提醒：每轮游戏制作、软著或发行任务收尾时主动复盘；有已验证、可复用的新经验或用户明确纠正时，当轮回收到 DEMO007 默认分支，更新规范版本、适用范围和来源，并提交推送到 DEMO001～007 全部现有分支（含 main/master），回读远端核对。只有项目特例或未验证想法时留在所属项目，不为凑总结制造通用规则或空版本；同步受阻时记录具体未完成分支并在后续工作主动续办。此约定随实际任务执行，不表示无人开启任务时后台常驻运行。
- 制作方自检、用户确认、真实手机、平台审核与正式入口分别记录。软著按本次冻结版本与实际通知办理，不把其他项目的补正要求自动变成新功能前置。

## 用户配表工作约定

- 配置 ID 应遵循项目既有编号和分类分段规则，将条目插入对应 ID 段的合适位置，不默认追加到表尾。
- 配表时不新增无意义空行；插入、移动或删除条目后检查数据区，保持紧凑并保留有用途的分段和说明。
- 修改策划配置表后，使用项目现有导表工具导表并检查导出结果；Git 操作按上述仓库归属执行：Biu 三仓库留本地，个人仓库验证后由 Agent 提交推送。
- 配置说明、分析记录和检查日志保存到本次任务的工作目录，不写入实际配置目录（例如原始表格、csv_client、csv_server或客户端资源配置目录）。若当前工作目录本身就是实际配置目录，使用该聊天提供的独立工作目录保存说明，并告知用户保存位置。
- Biu 项目配表时，多个独立条件使用英文分号 `;` 分隔，例如 `Goods.goodsBuyCond` 应写为 `PlayerLevel|1;GameSeason|2`，不得用逗号连接。条件内类型与参数使用 `|`，多参数按既有解析规则使用 `:`；不要与奖励串或数组的逗号分隔混淆。修改条件后检查各条件能分别解析，导表后核对双端 CSV 和客户端配置中的分隔符。
