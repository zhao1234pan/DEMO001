# 软著材料制作与补正

版本：2026-11-14.1。经验依据：E-COPY-01～08，见[经验条目](../EXPERIENCE_REGISTER.md)。本章总结材料制作方法，办理动作按本次申请、官方表单和具体通知执行。

## 先确定这一次申请对应什么

登记名称、简称、版本、权利人、开发完成日期、发表情况、开发方式和权利范围按用户已确认的事实维护。用户确认后同步申请填写稿、说明书、源码材料、附件清单，删除已解决的待填项。日期不能沿用另一申请，也不能为获得登记倒填开发经历。

区分初次准备、已提交、已受理、补正、撤回、重新申请和已取得证书。材料自检通过不表示已提交，用户说“已提交”也不能写为“已发证”。已存在申请时先核对实际线上附件和通知，不根据本机文件名带“最终”猜测线上版本。

已有明确的信息不重复索取。仅整理材料时不额外索取无用途的身份证件、流水号或账户秘密。身份文件与实际申请材料按项目既有私有存放方式管理，不随通用规范分发。

## 固定源码和功能范围

记录冻结提交、标签解析到的实际提交、运行配置、构建指纹、版本显示和截图来源。带注释标签的标签对象 SHA 与源码提交 SHA 分别记录。后续开发继续推进时，登记材料仍对应冻结版，不移动旧标签或用新版画面补旧版材料。

先盘点实际运行文件、配置、角色、地图、模式、系统与可进入页面。引擎、依赖、研究源码、自动生成的重复核心和构建合并脚本不得重复统计为新增自编程序。开发留档、原创贡献说明与已经办理登记分别记录。

若补正需要修改软件本身，先记录实际代码、配置和构建变化，再核对交存材料与登记版本的对应关系。不能只在截图贴标题或修改画面数字，并继续声称源码未变。只有本次通知或已核实适用规则明确要求的功能才据此处理，不将其他项目的通知变成当前游戏的新增功能前置。

## 先建立覆盖表再写说明书

| 覆盖对象 | 至少登记什么 |
| --- | --- |
| 首页与进入流程 | 冻结版入口、实际名称与版本显示、章节和图号 |
| 角色与图鉴 | 实际外观类别、分页、详情、等级或未知状态，避免把模板条数当外观数量 |
| 地图与场景 | 可进入场景清单、清晰画面、模式与复用关系 |
| 核心操作 | 入口、点击或拖动、条件、结果、取消与返回 |
| 各种模式 | 开始、实际过程、结束、失败重试与返回；未实现模式不造章节 |
| 设置与保存 | 当前确有的功能、恢复路径、旧档或导入的必要限制 |
| 广告与奖励 | 真实可用条件、取消或失败、未配置时的行为；不伪造成功 |
| 最终材料 | 文件名、页码、图号、源码与构建来源、最终文件摘要 |

每个对象应能对应章节、步骤、图片和最终 PDF 页码。小缩略图、某一图鉴首屏、相同地图上的多个弹窗，不能自动代表全部角色、地图和系统已经展示。

页数、章节数、插图数、格式和渲染通过只是不同检查项。叮咚和百鬼的复盘都暴露：原稿已有操作骨架，仍缺内容覆盖；不能把“14页”本身当作失败原因，也不能靠凑页替代补全。

## 完整流程与截图

至少保留与描述相符的一段完整实际操作证据，按本次材料范围覆盖各模式和必要分支。核对关卡、波次、生命、资源、击退、按钮和结算是否相互一致。胜利图仍是初始波次和零击退时，不能据图声称完成战斗。

用于布局的直接状态设置、隔离测试进度、规则模拟和正常操作证据分别管理。功能盘点可按项目方法准备隔离进度；完整游玩过程与自然结算不能用直接写入胜负状态代替。来源写在制作记录中，不靠修改截图伪造过程。

保存原 PNG、采集步骤、运行版本和必要录屏；排除空白、纯灰、加载未完成和遮挡画面。检查图片的实际内容，不只检查图片存在与尺寸。原图正常后仍要检查它在最终 PDF 的显示比例、细字和裁切。

## 源程序与交存编排

完整源程序先确定文件顺序和统计口径，再按办理要求摘录；保存完整有序索引与逐文件摘要。不能逐个文件任意拼凑各自前后页，不能让软换行或空白排版行虚增源码量。完整程序行数、交存行数和文档版面行数分别说明。

一般鉴别材料的前后连续页、全量提交和每页行数等，按[国家版权局登记办法](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)及本次要求核对；不照抄旧的费用、纸质办理方式或平台流转时间。名称和权利人署名应一致。补正以实际通知及系统日期为依据，不能把通知中的日数改写成工作日。

程序材料逐页核对顺序、源行、页眉、版本、页码、长行续行和截断。ZIP 检查重复路径、大小写碰撞、绝对路径、路径穿越与逐文件内容。不能通过删掉真实来源、许可证、AI 辅助历史或修改署名来证明原创。

## 说明书按玩家的顺序写

沿用用户已确认的文字风格：在哪里、点击什么、发生什么、必要条件是什么。图注直接说明画面，例如“店员选择菜单”“挑战成功结算”。保留游戏真实按钮、角色、数值和条件，不机械改名或统一润色用户原稿。

“正常操作”“真实取图”“合法选择”“有效回调”“幂等”等核验或实现术语放在制作记录。玩家正文只保留理解功能所需的条件，例如未收到观看完成结果时不发奖励。自然措辞不能以删掉地图、人物、系统、关键限制换取。

## 定稿和上传前检查

1. 原稿保留，更新可编辑 Word 后重新导出唯一待上传 PDF，不能让旧 PDF 留在最终目录混用。
2. 核对 Word、PDF 的正文、全部插图、页码、索引与摘要；逐页看最终显示，不能只提取文字或抽查首尾。
3. 检查固定行高、中文网格、图片段落、表格跨页和长代码的版式影响；按内容安排篇幅，不缩图挤页。
4. 保存最终文件名、大小、页数、SHA256、冻结提交、构建来源和生成时间。
5. 在已授权办理范围内上传后，核对真实附件预览与回执；材料准备不顺带执行撤回、签章、提交补正或平台发布。

审核意见只支持它明确说明的结论。内容缺漏通知不能推断为“AI导致不通过”“代码抄袭认定”或“必须重写算法”。涉及来源核验、代码重写和登记办理时，分别保存依据与处理范围。
