# 验收证据与交付

版本：2026-11-11.4。经验依据：E-QA-01～07，见[经验条目](../EXPERIENCE_REGISTER.md)。

## 每项结论对应自己的证据

| 结论 | 需要的依据 |
| --- | --- |
| 工程和配置可用 | 本版本的类型、导表、资源、规则及必要构建检查 |
| 界面可理解 | 最终构建的原尺寸画面、真实字框、触区和关键状态 |
| 流程成立 | 实际输入推进、操作结果、连续后果、恢复与重开 |
| 数值有影响 | 同条件对照，记录适用策略与异常样本 |
| 手机和宿主可用 | 设备、系统、宿主、版本、输入与能力的实际记录 |
| 用户确认 | 用户明确的对应页面、状态或版本意见 |
| 线上已生效 | 真实平台状态与普通用户正式入口验证 |

通过、失败、未验分别记录。已知失败不能改写成未验，别的项目或旧版本结果不能填本轮通过。工程全绿、截图数量多、HTTP 200、上传成功都不能替代对应体验结论。

## 先定义覆盖再采集

按入口、页面、状态、主要动作、结果和返回建立清单。覆盖短屏、常规屏、最长文字、大数值、空值、不可用、等待、错误、分页首尾和叠加状态。共用组件修改后检查所有使用位置，新增状态追加编号，不丢旧意见。

UI 验收册沿用用户已确认的结构：原意见与本轮处理、普通屏与短屏新图并排、旧图折叠、搜索与编号跳转、本轮结论、备注、浏览器保存和导出。用户意见与制作方自检分开；新轮次不自动继承“通过”。具体视觉皮肤按目标游戏，不复制另一游戏配色。

测量外框之外还要检查实际字形、PNG 内部安全区、圆形控件的视觉中心与非透明轮廓。原尺寸局部、整页和动态画面分别看，缩小总览主要用于查缺页。

## 截图和录屏的来源

画面要显示已断言的真实状态，排除空白、纯灰、加载帧、错误入口和不对应版本。保存源码与构建指纹、原图、必要的前后状态和操作过程。

正常操作、隔离进度、直接注入的布局状态、规则模拟和宿主替身分别说明用途。完整通关、自然对局、真实广告和手机反馈不能由测试状态替代。不要篡改画面数字或隐藏失败证据来制作通过结果。

录屏开始尽快进入核心玩法；检查比例、旋转、声音、黑屏、加载和结尾，不把等待和准备步骤当作主要演示。平台转码后重新核对。

## 最终产物一致

核对源码提交或 sourceDirty、原表、导出清单、资源、构建指纹、目录文件列表、ZIP 摘要与平台包号。独立解压后检查引用和入口，不依赖开发目录、缓存和本机服务才可运行。

单文件离线 HTML、HTTP 生产页面、局域网地址、公开托管和小游戏包分别交付。iPhone 附件预览不保证执行 JavaScript；局域网可用不表示外地朋友可用；部署返回成功不证明匿名入口可访问。无法实测的环境保留未验，不用另一个构建的旧结果补齐。

软著 Word 修改后重新生成最终 PDF；平台包修改后核对最新自测入口；宣传、说明、截图和最终文件一起检查，避免“文件已更新但交付入口还是旧版”。

## 按改动风险验证

纯规范变化验证编码、链接、引用、版本和同步范围；不重跑无关游戏测试。玩法、随机、存档、奖励或技术产物变化才运行相应行为验证。失败修复先证明原失败条件，再检查新行为，不增加只复述实现的测试。

长任务可按实际完成的分片接续，保留初轮失败和后续修复。重复执行不算新增覆盖，控制样本不冒充长期自然体验。完成后更新当前状态与剩余问题，历史过程另存，避免首页堆积相互矛盾的“最新结论”。
