# 两台电脑接续

规范版本：2026-11-11.5。

项目文件经提交推送并在另一台取得对应提交后才能接续。聊天里的临时理解、本地记忆、个人技能、引擎安装和用户目录下的全局 AGENTS.md，不属于项目 Git 的自动同步范围。

## 开始工作

1. 核对实际 Git 根、origin、分支、HEAD、未提交和已暂存内容，保留本机未完成工作。
2. 读取根 AGENTS.md、GAME_DEVELOPMENT.md、GIT_WORKFLOW.md 及目标游戏自己的当前约定、状态和活动记录。
3. 检查 GUIDANCE_MANIFEST.json 的版本与摘要，运行 `python tools/sync-game-guidance.py --check`。
4. 按当前项目恢复依赖、引擎和本机路径，再运行本任务必要的验证。

规范已经分发到各默认分支和其他分支，另一台更新自己实际使用的分支即可读取；不要把“更新了 main”当作其他工作树也已同步。执行过程中新增的分支以[维护方法](MAINTENANCE.md)补查。

## 新聊天会读取哪些内容

另一台先取得包含规范的目标分支，再在 Codex 中从该仓库或其子目录开启项目聊天，并将该目录设为主工作目录。Codex 会自动发现路径上的 AGENTS.md 或优先级更高的 AGENTS.override.md；入口已经要求 Agent 主动读取根规范和当前任务分章。整套手册按需读取，不是所有文件无条件一次性注入。

不依赖另一台已经复制用户目录下的全局 AGENTS.md。若聊天没有绑定这个项目目录，或仓库只是多根项目的次要目录，就不能假定会自动发现它的项目指令。已经运行的旧聊天应先重读更新后的入口，不能只因后台 Git 拉取就假定旧上下文已刷新。

加载规则依据：[OpenAI 项目指令发现](https://learn.chatgpt.com/docs/agent-configuration/agents-md)与[项目主目录说明](https://learn.chatgpt.com/docs/projects?surface=app)。本轮核对日期：2026-11-11。

## 完成与交接

每轮交付前主动复盘。已验证、可复用的新经验或用户明确纠正，当轮回收到 DEMO007 维护源、更新版本并提交推送七仓库所有现有分支，回读远端。无需用户再次提醒；特例和待验证想法保持所属项目与状态，详见[主动维护要求](MAINTENANCE.md)。

个人仓库由 Agent 提交推送本任务改动并回读远端 SHA；Biu 三工作仓库由用户操作。源码、原表、导出、资源和状态共同对应同一版本，文档已推送但实现仍本地时要直接说明。

沿用项目现有状态与交接文件，必要时补[交接模板](templates/PROJECT_HANDOFF.md)。记录可直接继续的下一步、未验项、实际包、来源和仅本机内容，不为套模板建立第二份相互矛盾的“当前状态”。

本机 localhost 预览须在另一台重新启动，局域网地址不适用于外地朋友。密钥、登录态和工具安装单独准备，不把凭据内容放进共享规范。

## 个人全局规则

docs/team/GLOBAL_AGENTS.md 保存当前用户全局规则的可部署副本；另一台核对该机有效新增约定后再部署。即使未部署个人全局文件，项目的根入口也包含本仓库所需的范围规则。

在旧聊天中继续工作时显式重读新规范，不能假定运行中的上下文已经更新。[OpenAI 规范发现说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)建议用受版本管理的项目约定稳定传递规则；[记忆说明](https://learn.chatgpt.com/docs/customization/memories)将本地记忆作为辅助回想。
