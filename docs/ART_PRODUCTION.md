## 1. 已确认的量产方向

- 采用“清晰潮流贴纸角色与 UI + 简化森林绘本环境”的混合风格。
- 角色、敌人、道具图标使用圆润外形、清楚描边和少量大色块，保证手机小屏辨识度。
- 场景使用深蓝绿色夜森林、暖黄色便利店灯光和木质设施，但必须拆成可复用模块，不逐关绘制整张高细节背景。
- 保持 2D 轻俯视 3/4 视角；光源来自左上，柔和椭圆影子落向右下。
- 所有文字和数字由 Cocos 文本组件绘制，图片中禁止烘焙正式文案。

### 1.1 简洁 Q 萌限制

- 正式角色以旧版潮流贴纸效果图的“小巧游戏单位感”为基准，不制作高精度大头立绘式战斗角色。
- 角色保持约 2～2.2 头身，头部圆润但不能挤压武器、道路和邻近塔位；身份优先依靠物种、制服主色和一个大工具识别。
- 单个角色控制在 4～6 个主要颜色，只保留一层简单阴影和一个小高光；禁止毛发笔触、服装褶皱、重复徽章、细小口袋和过多材质反光。
- 使用统一深色粗轮廓与细奶油色贴纸外边，缩放到 64 像素高时仍需边缘干净、五官清楚。
- 环境使用大片草地、树冠和道路色块，减少约 40% 的碎叶、小花、商品、纹理和零散灯光；每个障碍物控制在 2～3 个主要颜色。
- UI 图标只保留一个核心物件和一个强调色，不用装饰纹、复杂透视与多层高光制造精致感。

3. 地图公共件优先一个空塔位底座、木箱、购物篮、盆栽，对应代码当前的三类障碍。草地和道路沿关卡数据绘制，路牌、石块等后置。
4. 触控热区、字号和安全区已接入；用户反馈后补齐顶部状态、倍速、暂停、道具、上下文操作和结算首轮皮肤，下一步在真实尺寸验收辨识度与点击便利性。
5. 普通纸袋、疾行红汽水罐、重型快递箱三类敌人已接入，下一阶段补入口、终点、小型便利店与必要场景模块。
6. 验证8～12名店员与敌群密度后，再扩充硬币命中、减速、热气、清障等特效与动作资源。

待机图不烘焙投射物；整只动物不能跟随程序炮管360度旋转。地面阴影需检查与镜像、后坐的配合，必要时独立绘制。

## 3. 运行时尺寸基线

以下为 `750 × 1334` 设计稿像素，最终可在真机测试后微调：

| 资源 | 主体建议尺寸 | 透明画布建议 | 备注 |
| --- | --- | --- | --- |
| 店员一级 | 高 64～72 | 96 × 96 | 描边与阴影不得超出安全边距 |
| 店员二、三级 | 高 72～88 | 112 × 112 | 通过配饰升级，不整体放大过多 |
| 普通敌人 | 高 40～52 | 64 × 64 | 保证同屏大量出现仍可读 |
| 疾行敌人 | 高 38～48 | 64 × 64 | 轮廓更窄，颜色明显区分 |
| 重型敌人 | 高 52～68 | 80 × 80 | 不超过道路有效宽度 |
| 建造底座 | 72～80 | 96 × 96 | 视觉弱化，点击区仍为 88 × 88 |
| 单格障碍 | 64～80 | 96 × 96 | 清除后完整露出同一塔位 |
| 道具图标 | 56～64 | 80 × 80 | 不包含按钮底板与文字 |

当前敌人图集为统一脚底锚点采用168×168纹理切片、96×96设计像素透明画布；实际主体仍按上表高度控制，重型宽约86.9，不超过96设计像素道路。透明画布不代表碰撞、点击或主体尺寸。

## 4. 文件与导出规则

- 源图和未切分母版放入 `source_assets/art/production/v1/`。
- 游戏运行图通过尺寸与透明边缘检查后可接入 `assets/art/` 对应分类进行开发验证；正式发布前必须补齐真机可读性检查，不能以接入完成代替发布验收。
- 文件名使用英文小写 `snake_case` 与类型前缀，例如 `spr_staff_doubao_idle_v1.png`。
- 透明角色、敌人、障碍物和图标必须导出真实 Alpha，不使用棋盘格或纯色假透明背景。
- 图片型UI面板按九宫格制作；本轮按钮与面板底板采用可缩放矢量绘制，无需额外导出整幅面板PNG。角色、敌人、UI、特效分别组图，单张图集不超过 `2048 × 2048`。
- 量产资源保留至少 8 像素透明安全边距，裁掉无意义的大面积透明区。

## 5. 验收门槛

- 缩放到实际运行尺寸后，角色身份、敌人类型和塔位状态仍能在手机屏幕上一眼区分。
- 一屏 8～12 名店员与大量敌人同时出现时，轮廓不互相粘连，道路和入口仍然清楚。
- 新资源能在前 3 关的 22 个规则建造单元中复用，不因单张图好看而破坏布阵密度。
- 资源进入运行包后检查 DrawCall、图集尺寸、透明叠加和抖音低端安卓性能。
- AI 生成图先作为原创方向和生产底稿；进入正式版本前必须检查结构错误、边缘、透明通道、角色一致性和可能的近似风险。
