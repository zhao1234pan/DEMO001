# 产品方案

## 定位

- 游戏名称：叮咚夜班开始
- 早期工程代号：守护芽芽
- 世界观主题：森林夜班便利店
- 玩家代表：小浣熊夜班店长
- 首批店员：仓鼠豆包、垂耳兔棉棉、柯基布丁
- 类型：原创竖屏动物休闲轻塔防
- 目标平台：抖音小游戏、微信小游戏；当前发布能力以各平台独立验收为准
- 变现：IAA，以玩家主动触发的激励视频为主
- 单局目标：60～120 秒，单手点击，失败后可立即重试
- 氛围：温暖治愈、轻松幽默，带少量夜间神秘感

完整世界观基线见 [WORLD_BUILDING.md](./WORLD_BUILDING.md)。
完整玩法边界见 [GAMEPLAY.md](./GAMEPLAY.md)。

## 核心循环

进入首页 → 继续最高已解锁关卡或选择已解锁关卡 → 观察路线、空地和障碍 → 部署店员形成初始防线 → 在守路与清障之间分配火力 → 用清障零钱和新空间继续建造、升级或出售转移 → 营业到天亮 → 进入下一关或返回首页。

## 首版规则与当前实现（0.5.0，2026-09-29）

- 首页显示正式游戏名、最高已解锁进度和双列10关入口；“继续闯关”进入最高已解锁关卡，已解锁关卡可重玩，未解锁关卡不能进入。
- 暂停页可选择“结束本局并返回”，胜负结算页可返回首页；再次进关从开局开始，不恢复离开前的布阵、波次或零钱。
- 正式重玩不降低解锁进度，GM测试与正式进度隔离；不新增星级、逐关成绩或“十关全通”标记。
- 本地存储读写异常不阻断启动、结算和倍速选择，会话内保留可用值；存储失败时不保证关闭游戏后保留此次进度。
- 首批10个连续关卡，当前第1～9关4波、第10关5波，自动出怪；更长波次只作为后续测试选项。
- 每关一条独立且清晰的路线、22个规则化建造单元；开局12个空位、10个障碍，通过清除同网格障碍逐步释放。
- 0.4.0将十关塔位收为3～5组连续地台，取消孤立点，一级豆包对每格的解析有效路径覆盖不少于90逻辑像素；入口与便利店终点对齐真实路线端点并位于画面内。点位整理保留基础数值，但几何与开放顺序变化仍须体验验证。
- 首发豆包、棉棉、布丁；长期角色池扩展到 8～12 名。
- 店员最高 3 级；点击有效空地后选择店员，点击已有店员后显示范围、升级和出售；点击障碍物可指定清障，首版不提供拖动换位和分支升级。
- 冰柜冷气、闭店清场、紧急零钱为三个一键全局道具。
- 局内顶部常驻 1、2、3 倍速切换；它是面向所有玩家的正式功能，选择会跨关卡、重开、复活和再次启动保留。
- 每波出怪前在入口显示“下一波”和数字倒计时，提示结束后开始计时；当前首波/波间/复活等待4.2/4.8/5.3秒，向上取整会从5或6开始。
- GM仅供调试，入口在左下角，测试关卡与正式解锁/最高纪录隔离；它不进入正式玩家流程。
- 操作文字最低按24设计像素处理，按钮使用统一绘制/命中矩形；系统安全区与平台顶部胶囊参与布局。极短安全区允许缩小塔位热区防止相邻格误触，需在真机上验证降级体验。
- 不做星级评价、补货小游戏、三消、合成和复杂局外养成。

代码内部仍保留少量 `Tower` 等通用塔防类型名，但玩家可见文案统一使用动物店员、夜班零钱和赶走/安抚精怪。

成熟休闲塔防的玩法、UI、交互和逻辑拆解见 [TOWER_DEFENSE_REFERENCE.md](./TOWER_DEFENSE_REFERENCE.md)。本项目只借鉴通用结构，角色、场景、店员设备、敌人、UI 造型、音效和关卡均保持原创。

## IAA 设计原则

以下是目标边界。0.5.0按用户要求保持广告代码和流程现状，未修复缺配置直接奖励或异常状态复位；正式ID配置、广告位、真机和发布验收仍未完成。

1. 广告必须由玩家明确点击触发，按钮清晰标注“看广告”。
2. 不把广告作为正常开局或关卡解锁的强制条件。
3. 首版提供失败复活和道具补充：每关每类广告救援都有明确次数上限。
4. 广告未填充、API 不支持或调用失败时提供不中断游戏的兜底。
5. 正常关卡必须存在不看广告的通关路径；广告用于减少失败后的重复时间。
6. 插屏只考虑完整关卡结算后展示，并设置会话级频控；MVP 不接入。

## 美术与知识产权

2026-09-27用户选定B「便利店庭院」：当前入口更新为地铁口，终点仍为便利店；保持浅色铺装、砖缝和成组建造区。环境装饰采用固定米灰石花池/圆团小树，和棕盆可清障植物区分。0.4.1只更新地图表现，不扩展玩法或广告；以下0.3/0.4资产统计为历史。

动物店员、夜间精怪、便利店、地图和 UI 均采用原创设定。禁止直接使用或临摹其他游戏及现实便利店品牌的商标、包装、角色轮廓、关卡、美术、音效和文案。

简洁Q萌、小巧贴纸单位的方向已获用户认可。0.3.0接入三名店员、公共底座、三类障碍、三类怪物和道具图标；0.4.0增加森林入口、迷你便利店、低对比灌木，当前`battle_art`共五张512×512图集，PNG合计533,548字节（约521 KiB），不等于发布包体或纹理内存。旧椭圆底座切片保留兼容，但战场已改用成组的圆角地台。

UI延续奶油描边卡片、心形耐久与橙绿操作色；0.4.0统一便利店遮阳棚条纹、宽道具卡、暂停/胜负面板和地标标签。道路随真实路线程序绘制，增加圆角路缘、稀疏接缝及分段色调，不用十张大背景锁死关卡。多帧动作、升级配饰、店长和更多场景模块仍后置；代码接入不等于手机操作或低端机验收，实际结果以测试记录为准。

## 当前开发与发布范围

0.5.0优先补基础稳定性和玩家入口，最小计划见[基础功能计划](./FOUNDATION_PLAN.md)。本轮不增加角色、关卡事件、局外养成或广告点位。软著申请暂缓，未冻结登记版本；产品文档、测试证据与后续材料均按实际功能维护。

微信小游戏基础信息已提交，正式App ID已取得并用于独立目标构建；后台名称结果仍待核验。开发者工具运行、微信平台适配与真机尚未验收。两平台发布事项分别见[抖音准备](./DOUYIN_RELEASE.md)和[微信准备](./WECHAT_RELEASE.md)。

## 首轮验证指标

当前十关配置检查和混合店员加免费道具的1/2/3倍速机器演练用于发现逻辑故障；没有真实用户的完成率、留存或广告商业数据，不能将机器可通关当作人工胜率。

- 首局完成率
- 首局失败波次分布
- 三类塔的建造占比和升级率
- 平均单局时长
- 激励广告请求、拉起、完整观看和奖励发放成功率
- 次日留存（有真实流量后）
