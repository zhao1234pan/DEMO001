- 默认分支：`main`
- Fork 客户端：打开本地仓库 `G:\DEMO001`，即可查看提交树、分支和远端同步状态。

## 提交原则

重要且已验证的变更应形成独立提交并同步到 GitHub，包括：

- 新玩法、关卡、系统或平台能力。
- 修复影响运行、数据或发布的问题。
- Cocos、抖音平台、包体或构建配置变更。
- 产品规则、架构、发布流程和测试标准变化。

临时实验、未完成代码、构建缓存和日志不提交。辅助文件继续放在 `G:\gptwork`。

## 标准步骤

1. 查看工作区状态，确认没有无关文件。
2. 执行 TypeScript 检查和与改动风险相匹配的构建/测试。
3. 同步更新 README、产品、架构、测试、路线图或更新日志。
4. 检查差异后创建单一主题提交。
5. 推送到 `origin`，再确认本地分支与远端一致。

## 提交信息

建议采用 Conventional Commits：

- `feat:` 新功能
- `fix:` 缺陷修复
- `docs:` 文档
- `refactor:` 重构
- `test:` 测试
- `build:` 构建或平台配置
- `chore:` 维护工作

示例：`feat: add rewarded revive flow`

## 分支建议

- 稳定、已验证的版本保存在 `main`。
- 较大功能使用 `codex/<topic>` 或 `feature/<topic>` 分支，验收后合并。
- 不对共享分支使用强制推送。

## 安全规则

- 不提交账号密码、访问令牌、签名文件或私钥。
- 正式 App ID 可以进入平台构建配置；广告位 ID 是否提交由发布策略决定。
- 环境秘密使用本地或平台安全配置，并确保被 `.gitignore` 排除。
