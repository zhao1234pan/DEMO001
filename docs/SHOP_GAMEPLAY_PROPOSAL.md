# 独立便利店经营玩法方案

日期：2026-10-11。状态：玩法建议，待用户确认；游戏仍为1.7.4。

用户已经明确：商店要成为可以独立游玩的轻量模拟经营。顾客进店、选货、排队、付款构成自己的经营流程。本文替换此前按战斗波次售卖的方案。冒险首通可以提供新品，经营所得可以购买挑战补给；商店营业本身由顾客和商品驱动。

## 玩家进入的是一家正在营业的店

商店打开为固定视角的便利店内景，沿用现有治愈、明亮、圆润的PNG画风。门口、两组起步货架、收银台和动物店员都在同一屏内，顾客会自己走动、拿商品、排队，购买后提着小袋离开。玩家用点按指挥或帮忙完成操作。

顶部显示局外金币和返回入口；货架直接显示商品与剩余数量，顾客头顶用商品图标表达想买什么。下方提供商品、店员、改造和收款几个必要入口。更换商品与升级使用小弹窗，场景里的物体承担主要操作，不把经营页做成密集列表。

每次进入可以玩几十秒到几分钟，想继续开店就继续。店员有基础自动工作，玩家主动操作能改善效率，并观察自己选择的商品是否适合来客。

## 补货和结账带来直接操作乐趣

开店自带一名基础店员，自动处理补货和收银，优先服务正在排队的顾客。玩家点空货架，店员会提箱走过去补货；点收银台，可以帮当前顾客快速结账。搬箱、商品摆满、扫码、金币和购物袋都用简短动画给反馈。

补货免费，库存以货架格数为上限。新手不会因为进货花光金币而停业。玩家点按的是一整次操作，例如补满这一组货架，而不是连点十次逐个摆商品。操作请求不能靠反复点击重复补货或重复结账。

后续能雇佣一个帮手，分开负责理货与收银。店员逐渐接手重复工作后，玩家更多时间用来换货、应对来客和改造店铺。已有店员形象可用于经营岗位，经营雇佣和战斗四人阵容各自管理，不占用出战名额。第一版先区分岗位，经营专属技能后续再设计。

## 选什么货有意义

每个货架放一种商品。起步货架有限，玩家要从已解锁商品中选择搭配。顾客有偏好，有的想买一件，有的会买两件：

- 兔子学生常买面包和牛奶。
- 小熊上班族偏爱饭团和饮料。
- 夜归的小猫喜欢泡面或夜宵。

具体形象和偏好只是草案。顾客想买的商品必须已经解锁；拿齐偏好商品或双件订单时，会多买一件或留下小费。没找到时可以选择现有替代商品，空店才会导致空手离开。这样熟悉的低价商品仍可能靠搭配获得更好收益。

例如只有两个货架，摆两种高价零食可以卖得贵；换成面包和牛奶，则更容易满足学生的双件购买。玩家能从顾客拿了什么、留下多少小费看懂结果。信息由商品图标、购物篮和结账反馈表达，不增加讲解搭配的长提示。

普通客流自动到店。门口另有一次点按的招呼动作，冷却结束可邀请一小批客人。招呼前是否先补货、排队太长时先帮收银还是先扩库存，形成短时间内的选择。第一版先做正常来客与双件订单，再加入招呼客人；不靠持续连点才能维持客流。

## 金币先让自己的店变好

主要成长是可见的门店变化，而非只看收入数字增加：

| 投资 | 玩家得到什么 | 画面反馈 |
| --- | --- | --- |
| 升级货架 | 库存更多，补货频率下降 | 从简单货架变为更整齐的展示柜 |
| 改进收银台 | 自动结账更快，排队减少 | 新收银机、柜台装饰和更利落的动作 |
| 增加货架 | 同时上架更多商品，满足更多偏好 | 店里真的多出一组可使用的货架 |
| 雇佣帮手 | 理货和收银可以同时进行 | 第二位店员在场景里工作 |
| 更换装饰 | 按喜好布置便利店 | 门牌、灯、盆栽、桌边装饰直接换图 |

首版两组货架起步，最多四组。装饰使用固定位置更换款式，新增商店先完整确认布局。正式制作继续遵守独立PNG、相同槽位尺寸和XLSX导表，首页与现有图鉴的用户确认排版继续作为基线。

一个可见目标是先让店铺摆满货，再请一个帮手，随后把空角落变成新的售卖区。顾客购买记录还能增加商品图鉴的累计售出数，商品收集与实际经营发生联系。

熟客、纪念小物和更多主题装修适合后续扩展。第一版先让三类动物顾客拥有能辨认的偏好，场景里有生气即可，不同时新增完整熟客图鉴和大量剧情。

## 一分钟里的具体体验

玩家进入店内，看见面包架快空、收银台有两位客人。先点货架，店员提着箱子补满；再点收银台帮客人结账，钱进入柜台收款区域。

一位兔子头顶出现面包和牛奶。玩家暂时只卖面包与零食，于是把零食架换成牛奶。之后兔子买齐两件，付款并留下小费。下一次兔子来访时，玩家已经知道它喜欢什么。

货补齐、队伍变短后，玩家点门口招呼来客，看着几个小动物走进店里。攒够钱可以选择先扩货架，或请帮手提高自动处理效率。每次动作都改变店里正在发生的事情，营业可以接着进行。

## 首版数值只用于估计节奏

| 参数 | 原型起点 |
| --- | --- |
| 起始货架与上限 | 2组，后续最多4组 |
| 每架初始库存 | 6份 |
| 起始商品单价 | 3局外金币 |
| 自然来客间隔 | 约10秒 |
| 自动结账耗时 | 约8秒 |
| 主动帮助后耗时 | 约2秒，包含动作等待 |
| 补一组货架耗时 | 约2秒，行走时间另算 |
| 双件订单初始占比 | 约30% |
| 首次小升级目标价格 | 60金币 |
| 第一个帮手目标价格 | 80金币 |
| 第三组货架目标价格 | 120金币 |

以每分钟6位客人、平均购买1.3件、单价3估计，货物充足且完成付款时每分钟约23.4金币；双件订单小费另计。主动经营两分钟目标收入约40至60金币，首个小升级大约两至三分钟可完成。这里没有把额外客流或全部顾客都会成功购买计算为保证收益。

以上是本项目的原型试算，不是参考游戏的实测数值。还要考虑走路、补货、排队和缺货，收入需通过真实原型测试。此前按战斗波次算出的90至135金币收入和补给定价依据作废；补给价格要按新的经营收入重新评估。

## 与原有系统的连接

商店首次进入就提供基础商品和开店设备，可以直接营业。此前每关首通解锁一件商品的方向保留为新品来源：建议2件基础商品加20件冒险新品，共22件；具体名称和解锁顺序待统一排表。挑战通关与战斗波次不生成销售额，塔防倍速也不影响商店营业速度。

局外金币优先用于经营升级、雇佣和装修，也可以购买原有计划的一次性挑战补给。补给仍按单局携带一种的方向约束，商店收入不直接累加到战斗金币。经营道具购买界面可放在商店的一个小入口，店铺日常画面突出顾客与货架。

第一版先完成在店内营业和离开时保存状态。离线经营、时间上限和自动店员的后台收益下一阶段单独评估，避免在核心体验尚未验证时引入新的等待体系。

## 第一版制作范围

先做一个固定内景、两至三组可用货架、基础商品与首通新品展示、一名基础店员和一个可雇佣帮手、三种顾客、补货、结账、双件订单、小费、收款及两类设备升级。金币从真实顾客付款产生，形成独立的经营循环。

第一轮验证要回答：玩家一分钟内是否有事做，点按是否有直接反馈，选择商品和升级是否能改变经营过程，以及店员接手后是否仍愿意观察店铺。确认这些体验，再扩到四组货架、全商品、招呼客人和装饰。挑战扩关继续保留独立设计，不与这轮经营原型一起改数值。

自愿激励广告可在体验确定后考虑临时帮手或来客团，免费补货、自然顾客和正常营业完整提供。广告适配仍沿用项目已有平台边界，不在设计阶段增加外部服务。

## 配置与存档设计方向

规则确认后，先制作Goods、ShopRule、ShopCustomer、ShopStaff、ShopUpgrade、ShopLayout或复用UiLayout、ChallengeSupply和I18的原始XLSX；商品价格、库存、顾客偏好、订单、行动耗时、奖励、升级、岗位、资源与文案全部导成客户端CSV。现在不把草案数值写进代码。

经营状态保存货架SKU和库存、顾客购物篮、岗位、升级、待收款和钱包。商品取走时预占，真实付款时才产生待收款；每笔交易使用唯一顾客订单号，只提交一次。角色动画回调、页面重开和读档均不得重复发钱。切换商品时已有购物篮价格保持，避免按新价格结旧订单。

商店独立处理营业时间与顾客行为，战斗胜负、波次和战斗倍速不触发经营收入。开店初始状态、已解锁新品和首通迁移另有明确存档规则；GM展示不写正式商品和收入，GM重置覆盖新增经营存档。
