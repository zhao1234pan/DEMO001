# 玩家入口、战斗操作与适配规范

适用版本：0.6.0。以可玩棋盘为准，不把概念效果图当作坐标稿。设计分辨率750×1334，逻辑宽390，逻辑高693.68；普通缩放系数750/390。本文件描述实现规则，实际验证范围见TESTING，不能代替真机验收。

## 玩家操作

| 目标 | 操作与反馈 | 限制 |
| --- | --- | --- |
| 冒险入口 | 主界面点“冒险模式”进入大图选关 | 每页4关、共3页；正式首页初始化/战斗返回后默认定位最高解锁页 |
| 正式选关 | 点已解锁关卡大图；上一页/下一页翻页 | 大图对应真实路线与塔位；锁定项点击只显示解锁条件，重玩不降低进度 |
| 挑战入口 | 主界面点“挑战模式” | 仅提示准备中，不开始战斗、不发奖励 |
| 游戏图鉴 | 点怪物/BOSS/店员页签，再点图片查看详情 | 锁定卡片和详情显示剪影问号及解锁条件，BOSS预留本版始终锁定 |
| 声音设置 | 点音乐或音效开关 | 两者独立、本地保存；关音效立即停止当前音效，关音乐停止音乐 |
| 返回首页 | 暂停页点“结束本局并返回”；结算页点“返回首页” | 重新进入从开局开始；离开后清除本局对象，不保留局中快照 |
| 建造 | 点成组地台中的空格→点店员和标价→扣钱、出现角色与范围 | 不拖拽放塔；不足钱不扣款；已占用格不能重复建造 |
| 升级 | 点已有店员→点升级及费用 | 三级上限；钱不足与满级显示不可用 |
| 出售 | 点已有店员→点出售及返还金额 | 返还累计投入65%向下取整；原位恢复空地 |
| 清障 | 点木箱/篮子/盆栽→显示耐久与奖励 | 店员优先打敌人，空闲时清理指定障碍；清完原位可建造 |
| 道具 | 底部右侧冷气、清场、零钱三个按钮 | 首次免费，之后沿用既有实验广告流程，本轮不调整 |
| 倍速 | 右上×1→×2→×3循环 | 正式功能，跨局保存；计时和战斗共同加速 |
| 暂停 | 右上暂停→继续营业 | 不推进计时；切后台也暂停；暂停时改倍速不推进战斗 |
| 取消 | 点菜单外空白处 | 只取消当前选择；弹层外点按不会穿透 |
| GM | 调试版左下GM→1～10关；返回正式进度回首页 | 打开时冻结战斗；不写正式解锁或最高关纪录；发布版无入口 |

主界面、选关、图鉴和设置都不推进波次或战斗，不响应战斗建造/道具按钮。菜单按钮的绘制和命中共用矩形；弹窗存在时整页只接收弹窗按钮，关闭点击不能穿透。选关页显示“已解锁 N / 10 关”，不把第10关已解锁表述为十关已通关。MapReview跳过菜单，不写正式图鉴。

设置仅使用音乐、音效、版本和返回，删除氛围副标题、开关副说明、重复保存提示与无关页脚。隐私/服务政策使用宿主机制与后台要求，不在游戏内复制可选入口、不自编政策、数据说明或帮助反馈弹窗；宿主反馈不作为本游戏已实现功能。其他功能页保留必要的锁定条件、操作结果和错误提示；少量氛围文案限于主界面与图鉴故事。

触摸按同一触点ID管理，每次只接收一个主触点；移动过程中距起点超过24设计像素即锁定本次取消，即使滑远后回到起点也不能触发操作。第二触点进入时取消当前点击且不替换首触点；非主触点的移动/结束不触发按钮。系统取消或切后台清理本次触摸；结束时再复核位移与取消状态后，才反算到逻辑坐标。文字、底板与透明热区分离，不能按角色PNG大小判断点击，也不能只比较松手位置来判断是否滑动。

0.5.0曾复现A按下→B按下→A松开→A再次按下/松开且B始终未松时误触。0.6.0以`activeTouchIds`持续跟踪仍在屏幕上的触点；只要仍有残留手指，就保持点击取消状态。代码已修，最终专项须覆盖该交错序列、系统取消和后台清理；不能据主指取消检查宣称所有设备多触都已通过。

最高解锁和既有最高关纪录通过`setMaximumInteger`保存：先读取旧存档，将旧档、会话值和本次值向下取整并夹到0～10后取最大值。旧档读失败时只保留会话值、不落盘；下次读取该键尝试恢复合并和保存。没有后台定时重试，也不保证未落盘进度跨重启保留。倍速使用普通`setNumber`覆盖选择，允许降速；不能给倍速套用最高纪录合并规则。

入口倒计时优先沿首段路线方向偏移90逻辑像素，再夹到安全范围。先检查附近6个候选（首选、左右对侧及上下备用点），用96×80保守框避让当前建造卡片、升级/出售按钮和清障信息；仅当近处候选全部冲突时，才在棋盘范围按48逻辑像素步长搜索候选，并按离原首选位置的距离排序，取首个不与这些操作面板重叠的位置。该搜索是提示框避让，不是可建空地或寻路判断；若仍无可用候选则退回首选，后续布局扩展必须继续验证这一边界。只移动显示位置，不隐藏数字、不缩短计时或缩小字号；具体实屏验证以TESTING为准。

## 尺寸与避让

- 普通常规按钮透明热区至少88×88设计像素。基础底板：倍速/暂停50×48逻辑、道具88×64、升级/出售96×48；三个道具x分别为92/188/284、相邻间隔8逻辑像素。小屏安全高度收紧时自动扩展透明热区。桌面缩放后的CSS像素不是设计像素承诺。
- 建造选项采用64×84逻辑的肖像卡，按74逻辑间距组成一组，边缘整体避让，不逐个夹紧导致重叠；上下比较道路遮挡程度，候选中心离选中格至少60逻辑。升级/出售间距10逻辑，始终作为一组，候选中心离选中格至少48逻辑。
- 普通750宽棋盘格位热区为46×46逻辑，即约88.46×88.46设计像素；边缘热区夹在屏内，与相邻格位留缝。
- 极短安全高度或横向安全边距过大时，棋盘等比缩小。格位热区保持46逻辑避免抢邻格点击，此时显示像素可能小于88，这是明确的紧凑屏降级；不承诺在有限空间里同时维持22格、完整88热区和零交叠。优先支持16:9～20:9竖屏，异形真机仍需验收。
- 顶栏扩大热区时只向上扩，不侵入棋盘。当前塔位x=45～345、y=135～585，保留最高级角色的顶部和侧边净空；旧x=20/370的边缘格已内收。底部道具栏从`layoutBottom-85`开始，GM放左下，首尾地标和最下排必须按该实际底栏边界复核。
- 成组地台只组织视觉，不合并22个格位的点击判定；空格、障碍和清障后开放位置仍使用同一关卡网格。地铁入口、便利店、石花池与圆团树是场景素材，不可建造/清障，也不新增点击目标；棕色独立盆栽仍是可清障对象。
- 纯装饰布局由BattleSceneryLayout按关卡配置和完整画布校验；低花池48×48、小树40×56逻辑像素，不用透明范围或树冠覆盖塔位热区，不用自动散点填满空白。
- 入口/商店画布64×56逻辑、中心为路径点(x,y+6)；标签与终点耐久条合并范围为[x−32,x+32]、[y−40,y+34]。当前十关联合范围x=8～382、y=80～604，最紧第9关上下净空约5/4.68逻辑；实际字体、遮罩与菜单叠加仍需实屏检查。
- 辅助文字最低24设计像素；正文约28，操作文字约30～34，关键数值36左右，结算标题52。运行时按安全区缩放补偿最低字号，不用压小字强行塞文案。
- 最低边缘间距12逻辑（约23设计像素）；系统安全区之外再留按钮自身内边距。第一排靠边格位属于棋盘，遵循专门格位热区规则。

## 适配与平台边界

- 游戏本地之外，仅做抖音、微信、TapTap官方要求的必要内容；新增外部接入必须附对应官方要求依据，不默认加入可选功能或自编政策。TapTap仅纳入范围约束，本轮不新增其构建、SDK或发布适配。
- `BattleLayout.ts`集中保存战斗按钮几何和纯布局计算；`GameMenuView`集中管理主页、4关分页、图鉴、设置及弹窗的矩形，绘制和命中读取同一来源。菜单按可用安全高度等比缩放，不把缩放前的逻辑字号或热区当作全设备实际尺寸保证。
- 使用Cocos `sys.getSafeAreaRect(false)`，返回已是设计坐标、左下原点，禁止二次除DPR。
- 常规长屏固定宽度，棋盘等比居中、增加上下环境区；顶部状态贴安全区顶部，底部道具贴安全区底部，不拉长道路或角色。以`deviceScreen.windowSize`宽高比判断桌面短宽窗口并切换SHOW_ALL，完整容纳竖屏；只使用比例，不重复除DPR。切换前缓存策略，避免同步resize递归，不再使用已弃用的`view.getFrameSize()`。
- 抖音胶囊沿用`platform/douyin/DouyinLayout.ts`；微信新增`platform/wechat/WechatSettings.ts`，使用`getWindowInfo`与`getMenuButtonBoundingClientRect`获取尺寸。二者经`PlatformService`提供避让，缺接口或异常退回引擎安全区。两平台实际胶囊位置仍待开发者工具和手机验证。
- resize后更新位置，点击通过`contentRoot.UITransform`反算，不再用固定Canvas高度反算。
- 层级顺序：静态道路/成组地台→石花池/小树与地铁口/商店→选中范围→店员/障碍/敌人→血条/投射物/操作底板与弹窗→UI图标→文字。旧椭圆底座接口和素材保留，但正常战场不再逐格叠加。资源未就绪或失败时使用程序兜底或保留可读文字，不能阻断战斗。
- `contentRoot`矩形Mask宽390逻辑，高度跟随安全区域延展，裁去桌面黑边之外的地图、精灵和射程/特效。遮罩不改变布局和点击反算；不能把越界裁掉当成适配通过。
- 表现粒子最多200个，超出时省略新粒子，战斗与收益照常结算。该上限控制视觉开销，不替代低端设备帧率验收。

## 验收与交接

自动检查须包含：主界面入口、大图选关三页及最高解锁页定位、锁关提示、重玩不降解锁、挑战预留、图鉴正式出怪/旧档补录/店员随进度/永久BOSS锁定、弹窗拦截、独立声音开关与本地偏好、音乐异步加载/前后台/销毁、平台缺接口/失败/超时，暂停/胜负返回后重新开局、GM回正式首页、MapReview绕过首页、异常存储、旧档读失败时禁止覆盖、最高纪录读恢复合并、倍速降档和非法关卡ID，以及十关数据、成组地台与独立格位、首尾地标/标签/耐久条联合净空、清障可达链、倍速暂停、建造升级出售、GM存档隔离、750基准/长屏/安全区坐标往返、角落点按、滑远再返回起点仍取消、多触交错、系统取消、顶排防误触、倒计时避让和200粒子上限。机器策略通关只证明被测策略可行，不代表真实玩家胜率；有失败时必须保留原始结果。

实屏检查至少覆盖375×667、750×1334、375×812和375×834；以截图和实际点按确认精灵切片方向、菜单、清障、左右朝向和遮罩。0.6.0菜单须检查三个主页入口、四图分页、三页签、详情剪影、设置开关、提示及返回操作无溢出或穿透；声音需要实际播放和听验，不能只看开关状态。正式发布还需抖音及微信各自的开发者工具与真机检查，不可用浏览器代替。

0.4.1未改变路线、格位或基础战斗数值，60局固定机器策略与0.4.0逐局一致；不据此推断人工胜率。之后若改变路线长度、布阵位置或覆盖范围，仍须重做节奏对照。构建、策略与实屏的证据和限制见TESTING。

0.6.0先完成主界面→冒险→战斗→返回、图鉴锁定/解锁详情、声音开关及平台入口的集成检查，再延续第1/3/5/10关布阵、清障、难度和误触体验。图鉴13项、音频13项、平台24项及19项战斗/60局固定策略为截至当前的子模块证据；最终构建、实屏与触控以TESTING为准，不自动新增挑战玩法、广告、引导或局外养成。
