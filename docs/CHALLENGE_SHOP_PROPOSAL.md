# 挑战扩关与商品商店联动方案

状态：待用户确认。日期：2026-10-10。对应游戏基线：1.7.4。

建议先做一条完整循环：冒险首次通关解锁商品，在商店选择上架商品，战斗完成波次后产生销售额，回店收取局外金币，再购买下一局挑战的一次性补给。挑战由一关扩为四关，每关改变地图和来客节奏，保留已经确认的15波、十次免费三选一和四人阵容。

## 现有功能边界

当前有20关冒险、一关15波挑战、32张强化卡、8位店员和9件商品图鉴。挑战免费选择节点为0、1、2、4、5、7、9、10、12、13；每次选择可以成功看广告刷新一次。挑战原型每种道具各有一次免费使用，现金道具当前提供150战斗金币。

9件商品现在都按解锁关卡1展示，没有首通解锁、售卖或经营收入。1.7.4只把首页爱心隐藏、金币改为独立局外存档，初始余额0；下文的商品、收入、购买与扩关均尚未实施。

每关仍为15波，按当前十次选卡节点推进。第一版先复用32卡，依据出战店员和场地过滤候选；不为扩关同时增加大量卡牌。首领放在第5、10、15波，前两次为阶段压力，第15波为收尾。小怪和首领沿用数值特色，不新增复杂行为。

地图遵循当前已确认规范：道路平整，近邻道路之间尽量只隔一排塔位，开局塔位能覆盖有效路线；至少保留两种布阵思路。仓库关的清障收益应来自真实可用位置，不能用无意义障碍充数。

基准为当前挑战的来客总血量、单位速度、总奖励和单倍速时长。三张新地图先保持总血量与总奖励接近基线，再通过出生间隔、普通怪配比、首领配比和清障配置制造差异。初调总血量预算为基线的100%、100%、105%、110%，这只是试算起点，不能直接把倍率套到每波。

单倍速目标继续按6至8分钟设计；历史自动布阵基线约8分25秒，扩关前应先记录人工游玩时长，再决定缩短等待还是调整出怪。免费选择次数保持十次，不能靠压缩为更短关卡让选卡挤在一起。每关有独立通关记录，重复挑战不消耗入场资源。

## 简单售卖方式

商店保留最多三个上架位，选择已经解锁的不同商品即可上架。第1、2、3件商品解锁时分别开放一个位置，后续不再扩位。没有进货成本，不需要等待在线计时或反复补库存；商品是常驻经营品类。

每正常完成一波，当前上架的每件商品各售出一份。出战时锁定本局的上架商品和售价，局中换界面或退出重开不能修改已产生的销售额。已完成波次产生收入，未完成波次不结算；失败和主动退出保留已完成部分，通关不额外放大收入。这样重打第一关只能获得相应波数收入，不会拿到整局挑战的收益。

销售额先进入待收款，回商店点一次收取进入局外余额。未收款跨重启保留；上一局忘记收取也能继续玩，销售额继续累计。商店只需要上架区、商品列表、待收款和收取按钮，沿用现有PNG与圆体风格。首页和现有图鉴中用户确认的坐标、标题和标签不重新排版。

## 首版经济试算

| 参数 | 草案值 | 作用 |
| --- | --- | --- |
| 前10件商品每份售价 | 2局外金币 | 三槽每完成一波收入6 |
| 后10件商品每份售价 | 3局外金币 | 三槽每完成一波收入最高9 |
| 挑战15波全过收入 | 90至135局外金币 | 随上架商品变化 |
| 4波冒险全过收入 | 24至36局外金币 | 按实际波数结算 |
| 挑战冷气补给 | 90局外金币 | 下一局额外获得1次冷气 |
| 挑战金币补给 | 120局外金币 | 下一局额外获得1次现有现金道具 |
| 挑战清场补给 | 150局外金币 | 下一局额外获得1次清场 |

上述收入以三个上架位都已开放为前提。仅有一个商品时，每波收入2；两个时每波4。早期冒险第1关4波收入8，第2关两槽4波收入16，第3关三槽4波收入24，累计48；按同样4波预算玩到第5关累计约96，能买一次冷气。

首版只允许每局挑战携带一种额外补给，不能同时购买三种叠加。原本每种一次的免费道具保持；购买补给使所选道具额外增加一次。局外金币不直接进入战斗金币，不改变冒险初始金币、店员基础攻击或永久血量。现金补给通过现有道具效果提供当前配置的150战斗金币，两个余额始终分开保存和显示。

购买后保留在待携带栏；真正进入挑战、成功初始化本局时才消耗。返回配队、加载失败或重复点确认不能重复扣费，进局后失败不返还已经使用的补给。是否允许尚未使用的补给退回，可在试玩后另定；首版建议进入本局即消耗，规则保持一致。

按满三槽计算，冷气约一局收入，现金约一至两局，清场约一至两局。后期高售价商品是温和成长；玩法难度仍需以不购买额外补给能够通关为基础。第一版保持现有每次三选一的一次广告刷新，不追加经营广告位。

## 配置与存档边界

| 表或模块 | 建议处理 |
| --- | --- |
| Level、Map、MapPoint、Spot、Obstacle、Wave、WaveGroup | 扩充三张地图和三关数据，保留冒险20关上限 |
| ChallengeRule | 由单行改为每挑战关一行，选择节点、奖励、道具和波次均可配置 |
| ChallengeStage | 关卡排序、开放首通条件、标题、地图预览和记录关联 |
| Goods | 增加首通解锁关、售价、展示顺序，仍共用图片和I18 |
| ShopRule | 上架数量、开放条件、售卖触发方式和结算规则 |
| ChallengeSupply | 价格、对应道具、额外次数、携带上限和作用模式 |
| Global与I18 | 存储版本、独立钱包键、必要文案 |
| UiLayout与VisualSkin | 新商店及挑战选关布局、皮肤和独立PNG引用 |

先确认规则与字段，再制作原始XLSX、导表校验、CSV和客户端读取逻辑，不提前把草案数值写入代码。代码只处理波次事件、结算、过滤和购买事务。

钱包、待收款、交易序号和已消费记录应在同一版本化存档对象中提交，避免跨多个存储键半成功。每个收入事件使用runId加waveId，每个购买使用唯一交易号；重复结算、重进页面和旧局回调都不得重复发钱或扣费。GM测试不写正式经济，重置进度需要同步清理首通、商品、钱包、待收款和待携带补给。保留迁移测试与故障恢复记录，不新增服务端。

## 实施顺序与验收

建议先实现前三关解锁三件商品、三个上架位、波次收入、收取和一种冷气补给，打通从冒险到挑战的完整循环。通过后补全20件商品和另外两种补给，再制作三张挑战地图。现有一关挑战作为回归基线，不一次同时改变选卡节奏和商店收益。

验收需要覆盖首通与重打、旧存档迁移、失败和退出、加载失败不扣补给、重复领取、断电重进、GM隔离、购买上限、图鉴与商店同步，以及无补给完成四关挑战。所有新页面逐项对照确认图，保留实际运行截图；模型检查不能替代画面和真人试玩。
